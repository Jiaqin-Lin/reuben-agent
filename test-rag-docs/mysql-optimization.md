# MySQL 数据库性能优化策略

## 索引优化

索引是数据库查询性能优化的核心手段。

### B+Tree 索引

InnoDB 默认使用 B+Tree 索引结构。主键索引的叶子节点存储完整行数据（聚簇索引），二级索引的叶子节点存储主键值。

### 索引设计原则

- 为 WHERE、JOIN、ORDER BY 涉及的列建索引
- 联合索引遵循最左前缀原则
- 避免在索引列上使用函数或表达式
- 选择性高的列优先（如唯一键优于性别字段）
- 定期分析和重建碎片化索引

## 查询优化

### 慢查询定位

开启 `slow_query_log` 记录执行时间超过阈值的 SQL，使用 `EXPLAIN` 分析执行计划。关注 `type` 字段（从好到差：const > eq_ref > ref > range > index > ALL）。

### 常见优化手段

- 避免 `SELECT *`，只查询需要的列
- 大表分页用游标替代 OFFSET
- 批量写入使用批处理而非逐条 INSERT
- 合理使用连接池，避免频繁创建连接

## 表结构设计

- 字段类型选择最小满足需求的类型（如 TINYINT 存状态码）
- 避免过多字段的宽表，考虑垂直拆分
- 大文本字段（TEXT/BLOB）拆分到附属表
- 根据业务场景选择合适的分库分表策略

## 连接池配置

HikariCP 是 Spring Boot 默认连接池。关键参数：

- `maximumPoolSize`：最大连接数，通常设为 CPU 核心数 × 2 + 磁盘数
- `connectionTimeout`：等待连接的最长时间
- `idleTimeout`：空闲连接超时时间
